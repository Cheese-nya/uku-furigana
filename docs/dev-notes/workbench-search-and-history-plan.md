# 工作台查找、位置保持与注音修改历史

状态：已实现（2026-11-06），Chromium 桌面与移动模拟已走通全部验证项；Android WebView 真机尚未实测。本文只定义本次工作台功能，不包含云同步、正文编辑历史或阅读器搜索。

## 1. 用户问题与已证实的原因

用户在工作台误选“全文同词”后，与“人”相关的文字被改成同一读音；逐处滚动修改后又回到文章开头。删除文章并重新导入仍保留旧注音。

视频（约 18.8 秒，手机竖屏）显示：修改“人”的读音、应用后预览清空为加载骨架，再回到顶部。对照当前代码：

- `app/page.tsx` 的“全文同词”扫描 `cleanText.indexOf(surface)`，是**字面子串匹配**，所以“人”会命中“人生”“人間”等长词内部。
- `useFuriganaWorker` 只在新输入对应的完整快照到达时暴露行；每次修改读音都会使 `annotatedLines` 暂时为空，预览列表卸载，分页和滚动位置随之丢失。
- `correctionDatabase.resolveScript` 按正文指纹复用台本身份；`useLibraryController.handleDeleteBook` 删除的是书库条目，不删除校对。故重新导入相同正文会恢复旧人工注音，这是当前明确设计，不是注音引擎没有重跑。

阅读器已经处理了“重新注音时恢复原行”，工作台可借鉴其按行恢复的思想，不能仅保存一个像素 `scrollTop`。

## 2. 已确认的产品决策

| 决策项 | 结论 |
| --- | --- |
| 查找位置 | 工作台“注音预览”卡片内的搜索入口；点击展开，不放进拥挤的手机 ⋮ 菜单 |
| 查找方式 | 整篇原文的字面子串查找，允许命中长词内部；按文本顺序跨 200 行分页导航 |
| 修改后 | 关闭编辑弹层和键盘，留在当前命中处，由用户主动点“下一个” |
| 批量范围 | 保留字面子串能力，但“全文同词”改名为“全文相同文字”，执行前必须预览确认 |
| 已有人工注音 | 批量默认跳过；用户显式开启后才覆盖，并显示将覆盖的数量 |
| 重复行 | 新“仅此处”必须真正只修改当前行，不再因原文相同而联动 |
| 撤销 | 操作级撤销与重做；持久化，跨重启可用；冲突项默认跳过 |
| 恢复 | 单处可“恢复自动注音”；查找结果内可按“原文＋当前读音”批量恢复，先确认影响范围 |
| 历史 | 独立“修改记录”面板，只记录注音操作；每份台本保留最近 500 次操作 |
| 历史冲突 | 恢复历史时，后来又被修改的项保留现状并明确列出，不静默覆盖 |
| 正文/标题/词典 | 不进入这条注音操作时间线；全局词典仍有自己的管理界面 |
| 重新导入 | 保持人工校对，不暗中清空；在界面解释，并提供明确的恢复入口 |

## 3. 用户操作逻辑

### 3.1 查找和定位

1. 预览卡片的标题栏放“搜索”图标，旁边放“修改记录”入口；手机使用图标与可访问名称，不挤压正文。
2. 点击后在卡片内展开搜索条：输入框、范围选择（“原文”/“读音”）、上一个、下一个、结果计数、关闭。
3. 默认查找原文。输入“人”时列出所有字面子串，包括“人生”中的“人”，但定位只高亮实际命中的“人”范围，不能把“人生”整体作为修改对象。
4. “读音”查找平假名与片假名等价；输入 `ひと` 可找到 `ヒト`，不要求首版支持罗马音检索。读音来自当前已计算的注音，普通自动读音和人工读音都可搜索。结果以实际注音 token 范围为地址，不能以假名长度回推汉字偏移。
5. 初次命中默认从当前可见位置之后开始，找不到再循环到全文第一处；没有当前位置时从开头开始。计数显示“第 X / N 处”。编辑某一处后仍指向该项，结果总数可变化，但不自动跳到下一项。
6. 自动切到 `Math.floor(lineIndex / 200)` 页，将目标滚动到预览可视区域中间。高亮命中范围；点击该范围打开现有注音编辑弹层。手机在“原文”视图点击搜索时，先切到“注音预览”。
7. 查找范围只限当前文档，不上传搜索词。切换文档时清空搜索状态并取消旧定位；关闭搜索保留当前页和滚动位置。
8. 注音尚未完成时，搜索条显示“正在更新 N 处结果”，不能拿空数组冒充“无结果”；更新失败时保留上一次可用结果并标注“结果可能未更新”。

### 3.2 单处修改

- 默认仍为“仅此处”，作用地址为“当前文档＋当前行＋行内字符范围”，重复原文行不共享新记录。
- “应用”后关闭弹层与键盘，停留在当前命中位置；用户点“下一个”继续。不得自动打开下一处的编辑弹层。
- 编辑弹层新增“恢复自动注音”：删除该处人工覆盖，并清除该处学习读音；然后按“单处人工 > 原文自带 > 专名词典 > 上下文学习 > 自动引擎”的优先级重新计算。恢复自动是删除覆盖，不是写入一条空读音；“不注音”仍是显式人工覆盖。
- 对暂时没有人工覆盖的项禁用“恢复自动注音”，并说明它是自动/来源/词典读音。

### 3.3 批量修改与防误触

1. “全文同词”改为“全文相同文字”，避免把字面子串暗示成分词边界。
2. 选择该范围后先进入确认页，不立即写入。确认页显示：搜索文字、目标读音、总命中数、实际将修改数、默认跳过的人工修改数、位于长词内部的命中数。
3. 默认勾选“跳过已有人工注音的项”。用户显式开启“也覆盖已有 M 处人工注音”后才覆盖；确认页提供可展开的命中上下文预览，标明长词内部命中。
4. 整批作为一个原子操作写入，并记录一条历史。执行后留在原位置，提示“已修改 N 处，跳过 M 处 · 撤销”；不能只显示操作成功而没有数量。
5. 批量操作必须根据确认时的文档 revision 再校验；正文或相关注音已变化时要求重新预览，不能拿旧偏移直接写入。

### 3.4 查找结果内恢复

- 搜索条提供“恢复这些注音”入口，默认以“原文＋当前读音”为条件，例如只恢复当前读作 `じん` 的“人”，不误伤读作 `ひと` 的“人”。
- 确认页显示匹配数、实际有人工覆盖的项数、位于长词内部的项数；默认只删除匹配范围内的人工覆盖，不清除全局词典或原文件自带注音。
- 非人工读音无需“恢复”，不计入实际执行数。存在与该处关联的上下文学习读音时，一并按单处恢复规则清理。
- 一次批量恢复也作为一条历史操作，可撤销和重做。此入口用于修复已发生的误改，但不能声称能还原未记录的历史修改时间。

### 3.5 修改记录

工作台新增“修改记录”面板，按当前台本筛选，默认最新在前。

每条摘要包含：时间、操作类型、文字、读音变化、实际修改/跳过数量。例如：

> 11月6日 13:26 · 全文相同文字 ·「人」：ひと → じん · 修改 128 处，跳过 3 处

展开一条可查看逐处的行号、短上下文、修改前后读音、长词内部标记和当前状态。每个无冲突项提供“定位”和“恢复此项”；整条无冲突操作提供“撤销此操作”。

- 单处编辑、批量修改、单处恢复、批量恢复、撤销、重做都记录。
- 一次批量只生成一条操作记录，逐处变化作为该记录的明细，不能刷成几百条顶层记录。
- 历史随台本持久化，重新打开应用仍可查看。每份台本保留最近 500 次操作；一次批量算一次，不论其明细数。超过上限淘汰最旧记录，现存注音不受影响。
- 达到上限时，如果最旧记录仍是撤销栈底，须整段截断最早的连续历史，不能删掉底层记录却让上层撤销指向不存在的快照。实现中使用环形撤销游标及被截断边界，不能保留跨缺口的“重做”。
- 功能上线前已存在的人工校对仍可被查找和恢复，但不能伪造原读音、时间或操作者。历史面板可单独列出“现存的早期人工校对 N 处（无修改历史）”，定位到实际现存条目。
- 历史仅含注音操作，不记录正文输入、标题修改、专名词典或应用设置。
- 历史记录与搜索词只存储于本地校对存储；不上传到使用统计或错误日志。云同步若以后覆盖校对数据库，需单独评审容量与合并规则。

## 4. 数据模型与兼容策略

### 4.1 不把行号当成永久身份

当前 `RubyOverride` 以 `{ line, start, surface, reading, type }` 定位，同一内容的重复行共享覆盖。新版需要区分：

```ts
interface OccurrenceAddress {
  lineIndex: number;       // 当前文档中的行序号，仅作导航与提示
  lineText: string;        // 必须完整匹配，避免编辑后错套
  occurrence: number;      // 同一 lineText 在文档中的第几次出现，从 0 开始
  start: number;
  surface: string;
}

interface CorrectionChange {
  target: OccurrenceAddress;
  before: RubyOverride | null; // 该处操作前的人工覆盖
  after: RubyOverride | null;  // null 表示恢复自动
}

interface ReadingHistoryEntry {
  id: string;
  kind: 'edit' | 'bulk-edit' | 'restore' | 'bulk-restore' | 'undo' | 'redo';
  createdAt: number;
  changes: CorrectionChange[];
  skippedManual: number;
  substringMatches: number;
  supersedes?: string;        // 撤销/重做对应的操作 ID
  truncated?: boolean;        // 被保留记录之前的详情不可恢复
}
```

以上是逻辑模型，不要求把所有冗余地址重复写入每一条 `RubyOverride`。实现时可把 occurrence 放在行定位元数据中，并保留旧字段供原格式消费。历史必须保存覆盖前后的值；只保存“行号＋新读音”不足以撤销或判断冲突。

### 4.2 旧重复行记录

不能给旧记录随意补一个行序号后当成单处修改，因为旧数据无法证明用户当时想改哪一处。

- 没有 `occurrence` 的旧覆盖仍按“同一原文行全部适用”的 legacy 规则显示。
- 新“仅此处”在当前行写入 occurrence-specific 覆盖；该行的新覆盖优先于 legacy 覆盖，其他重复行的 legacy 规则保持原样。
- 对 legacy 行点击“恢复自动”时，先列出其会影响的重复行，确认后为**所有这些相同行**移除 legacy 覆盖；不能宣称只恢复了一处。
- 批量修改默认跳过人工项时，legacy 与 occurrence-specific 人工覆盖都算人工，不能误覆盖。
- 新全文批量写入每个实际行身份，重复行各自有明确地址；不再靠重复行内容隐式联动。
- 旧记录不伪造历史；只有新发生的操作进入时间线。

### 4.3 正文变化后的地址

- 同一行其他字符被编辑后，旧覆盖不应猜测偏移；继续遵守“完整原文行匹配，变化后待复核”的原则。
- 新增/删除前面的行使 `lineIndex` 变化时，可以按 `lineText + occurrence` 重新定位；`lineIndex` 仅用于导航，不是跨正文版本的永久身份。
- 当前行内容已变化、同一原文行的次序/数量发生变化而无法确定映射时，将历史项标为“原文已变化”，禁止自动恢复。首版不承诺任意正文 diff 的覆盖迁移。
- 搜索、编辑、确认、撤销都用同一 `documentId + textRevision` 校验；旧文档的异步结果不得写入新文档。

### 4.4 持久化

- 优先采用向后兼容的 v2 扩展：每个 script 增加可选 `history`，旧覆盖采用上述 legacy 规则；旧版应用忽略未知字段时会丢失历史，因此必须在发布说明标明“历史功能需要新版桌面/移动端”，不要静默宣称跨旧版兼容。
- 若验证发现现有原生/备份链路会剥离未知字段，再采用显式新存储版本和迁移，而不是绕过验证。桌面 `save_correction_database` 当前硬编码检查 version 2，任何根版本变化都要同步修改并测试。
- 历史与当前覆盖在同一个数据库快照中写入，沿用现有串行保存和原子替换；不允许出现“注音已改但历史单独丢失”的双写状态。
- 启动时校验历史条目，坏数据不得覆盖原库。500 条为操作数上限，另外设置单条批量明细/总存储的安全上限；达到安全上限时保留操作摘要并清楚标记“明细已归档/不可恢复”，不可假装完整可撤销。具体上限在真实长书压测后定，不预先承诺无限批量历史。
- 撤销与重做都在当前最新状态上执行，不恢复整个数据库快照，以免抹掉后续无关修改。

## 5. 撤销、重做与冲突算法

每个变更项记录操作前的人工覆盖 `before` 与操作后的 `after`，以及操作完成时该处的有效人工覆盖指纹。

### 撤销

1. 重新定位每一项；定位失败标为“原文已变化”，跳过。
2. 当前人工覆盖与该项 `after` 一致，才可还原 `before`。
3. 当前人工覆盖已不同（包括被后续操作改变或手动恢复），标为“已再次修改”，跳过。
4. 恢复 `before` 时，同时恢复该项关联的上下文学习记录；`after` 所产生的学习记录只移除本次添加的那一份，不能删除其他操作产生的同形记录。
5. 原子提交可恢复项，记录一条新的 undo 操作；结果明确显示“已恢复 X 项，跳过 Y 项冲突”。
6. 冲突项提供逐处对比：“操作前 / 操作后 / 当前”，用户可明确选择“采用历史值”；该选择本身是新的单处编辑，并记录历史。

### 重做

- 只有撤销实际还原的项才可按同样规则重做；当时冲突跳过的项不能随着重做被强制覆盖。
- 在新的注音编辑发生后，传统“下一步重做”分支失效，但历史面板仍保留旧操作供查看和逐项对比。
- 禁止跨历史缺口回放：500 条上限或安全裁剪使前置记录消失时，依赖它的撤销/重做链一并失效。

### 优先级提醒

“恢复人工覆盖”后的有效读音可能来自原文、词典或学习记录，而不是引擎默认值。历史冲突判断针对**实际人工覆盖快照**，不是仅比较 UI 最终显示的假名；否则词典变化会造成误判。若操作改变了学习记录或全局词典，历史摘要必须标明该副作用；本期全局词典修改不纳入单文档撤销。

## 6. 位置保持与异步注音

1. 修改 `useFuriganaWorker` 的快照策略：输入改变时仍取消旧任务并标记 busy，但继续暴露上一份**同文档**完成/部分快照用于显示；新 chunk 按行替换，完成后原子切换状态。
2. 保留快照只能在同一 `documentId`、同一正文 revision 的注音配置变化时使用。切换文档或修改正文必须清空旧文档显示，不能把 A 文档的注音盖到 B 文档上。
3. 编辑、撤销、恢复前保存逻辑锚点 `{ documentId, lineText, occurrence, start, surface, searchResultId? }`。异步更新期间 scroll 事件若因 DOM 变短而钳制到顶部，不得改写这个锚点。
4. 目标行重新渲染后，按锚点恢复页码和滚动位置；字体、换行或 token 数量改变时以行位置为准，而不是保存像素。
5. 用户主动翻页/滚动后更新锚点；异步恢复不得把用户强行拉回旧位置。连续恢复只进行一次明确导航，不循环抢滚动。
6. 修正编辑弹层的页码副作用：`openTokenEditor` 不能在仅修改读音、原文未变时再次把页码写回旧值；只有用户明确选择目标时才导航。
7. 保持旧的“过期响应不落地”规则。保留旧 UI 快照不意味着允许旧 Worker 结果进入新输入。

## 7. 模块边界与实施顺序

建议按可独立验证的四步落地，每一步保持现有导入/导出语义：

1. **数据与命令层**：扩展 occurrence 地址、旧规则适配、历史 schema、批量命令、原子撤销/重做及冲突检测。新纯函数放 `app/utils/`，不要把整套规则堆进 `page.tsx`。
2. **异步快照与位置保持**：改 `useFuriganaWorker`、`EditorWorkspace` 预览列表和定位锚点；先证明没有查找时普通编辑也不回顶部。
3. **查找与编辑 UI**：搜索条、跨页导航、范围高亮、批量预览、单处/结果内恢复、操作反馈。中英文文案进 `i18n.ts`，所有异步操作防重复提交。
4. **历史面板**：时间线、逐处定位、冲突对比、撤销/重做、历史裁剪提示；接入真实持久化和手机/Android 返回键关闭规则。

组件建议：`WorkbenchSearchBar`、`ReadingHistoryModal`、`BulkCorrectionPreview`，共享现有 `Modal`、`GlassButton`、`LiquidSelector`。所有状态归属工作台控制器，弹层关闭不销毁当前搜索/位置；换文档才清理。

## 8. 验收与测试

沿用项目的 Node 测试加载 TypeScript 方式，不为本功能引入另一套测试栈。除纯函数外必须做真实浏览器验证，因为本问题主要来自 DOM 卸载、分页与滚动，不是字符串函数单独能证明的。

### 数据与命令

- 两个完全相同的行：新“仅此处”只改目标行；旧 legacy 覆盖仍按原规则显示；新覆盖优先级正确。
- “人”在“人生”“人間”“人”中的字面子串计数准确；确认页的数量与实际写入一致。
- 默认跳过人工项，包括旧重复行人工项；显式覆盖时才替换。
- 恢复只删除目标人工覆盖及对应学习项，原文 ruby、词典、无关人工项均保留；空读音恢复后重新出现。
- 一次批量在历史中只有一条顶层记录，所有变更明细、跳过数、前后值完整。
- 500 条上限、撤销链截断、大数据安全裁剪、损坏历史加载均不丢当前注音。
- 撤销无冲突项、跳过后来修改项、重做仅处理已撤销项；原文变更/重复行重排导致无法定位时禁止自动回放。
- 保存失败时 UI 不宣称撤销/恢复成功；串行写入和原子性测试覆盖桌面桥接。

### 搜索与位置

- 搜索“人”跨 200 行分页定位，长词内只高亮“人”；下一处/上一处循环与计数正确。
- 读音 `ひと`/`ヒト` 等价；无结果、注音中、失败、空查询都有明确状态。
- 修改位于第 201 行之后的命中项，完成后仍在同一行，不回第一段，不自动打开下一项。
- 更新时旧快照可见但标为更新中；过期 Worker 响应不覆盖新结果。
- 手机键盘收起、旋转/尺寸变化、用户主动滚动后，不发生异步抢位置。
- 换书/重新导入时不展示前一本书的快照或搜索命中；旧人工覆盖按指纹保留且 UI 有解释。

### 历史

- 重启后仍能查看最近操作，逐项前后值、时间、上下文和跳过数正确。
- 撤销批量操作后，后来修改的冲突项保留；冲突对比采用历史值会生成新操作。
- 上线前人工校对显示为“无历史”，不能伪造修改时间。
- 中英文界面、手机底部弹层、Android 返回键、键盘可访问性均验证。

## 9. 明确不做

- 不把重新导入解释为清空人工校对，也不在删书时隐式删除另一套数据库。
- 不做正则、模糊拼音、罗马音搜索、整篇正文替换或正文版本历史。
- 不用 AI 猜测“正确读音”来回放历史；恢复严格依赖记录的覆盖与明确的引擎优先级。
- 不承诺无限历史、旧版应用完整兼容或任意正文编辑后的自动迁移。
- 不在没有预览、数量、冲突处理的情况下提供“一键清空所有注音”作为主要恢复方案。
